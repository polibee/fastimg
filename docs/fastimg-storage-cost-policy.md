# FastImg 存储、流量与成本策略

## 1. 成本边界

免费服务必须有明确的资源边界，不能以“免费无限”为产品承诺。所有额度由套餐配置并由服务端执行：

```text
存储空间
单文件大小
每日上传数量
月 API 上传次数
月外链流量
并发上传数
图片处理次数
批量下载大小
```

Free 用户可以完整使用核心功能，但超过额度后不能继续消耗平台资源。删除、导出和查看自己的已有内容应继续可用。

## 2. 存储计量

存储用量由以下对象构成：

```text
原图对象 + 派生 Variant + 未完成上传预占 + 回收站对象
```

- 回收站内容继续计入空间。
- 未完成上传预占必须有过期时间。
- 删除对象成功后才释放空间。
- 派生图默认计入空间，套餐可以配置是否只计算原图。
- 统计展示使用字节整数，不能使用浮点近似导致超额绕过。

## 3. 哈希与重复文件

上传完成后计算内容哈希，用于：

- 提示用户可能重复上传。
- 检测同一用户的重复对象。
- 校验分片合并完整性。
- 辅助孤儿对象扫描。

首期不做跨用户物理去重，避免删除、权限、计费和隐私关系复杂化。可以允许同一用户选择“复用已有对象”，但必须建立新的媒体记录和独立分享策略。

## 4. 存储 Provider

首期 Provider：

```text
Local       本地开发和离线测试
S3Compatible 生产候选接口
```

业务层只依赖 StorageProvider，不直接依赖云厂商 SDK。Provider 必须支持：

- 上传和分片合并
- 元数据读取
- 私有对象读取/签名 URL
- 复制和删除
- 存在性检查
- 错误分类和重试建议

真实生产 Provider 接入完成的证明必须包括真实连接、上传、读取、删除、失败恢复和孤儿对象检查；配置文件存在不算完成。

## 5. 流量计量

计费流量来自服务端成功响应的字节数：

- 原图、Variant、下载和批量 ZIP 分别记录。
- HEAD、失败响应和内部任务不计入用户流量。
- 管理后台预览是否计费由站点配置决定。
- 访问事件异步写入，不阻塞图片响应。
- 超出流量后默认阻止新外链访问或降级到限速页，具体策略由套餐配置。

防盗链只降低滥用风险，不能代替流量配额和异常流量监控。

## 6. 回收站和生命周期

推荐生命周期：

```text
active -> trash -> cleanup_pending -> physically_deleted
```

- Free 回收站保留时间由站点配置。
- Creator/Pro 可以拥有更长保留时间。
- 清理任务按批次运行，避免一次删除造成存储和数据库压力。
- 永久删除先进入 `cleanup_pending` 并阻止恢复；对象删除失败保留此状态，允许同一清理操作幂等重试。
- 清理完成后才写入释放存储的用量流水。
- 多个 Variant 引用同一对象时只删除一次；被其他媒体引用的对象在引用计费/清理策略实现前拒绝删除。

## 7. CDN 和自定义域名

CDN 不进入最初 Free MVP。接入前必须明确：

- 缓存 Key 是否包含 Variant 和签名参数。
- 撤销分享或删除媒体后的缓存失效策略。
- 私有链接是否使用短 TTL。
- 自定义域名的 DNS、证书和所有权校验。
- CDN 流量如何回写用户用量。
- 回源失败和热链保护策略。

自定义域名不能让用户绕过媒体权限、套餐流量和分享过期时间。

## 8. 成本保护策略

- 单 IP、用户、Token、域名分别限流。
- 新注册用户有上传冷却和每日上限。
- 大文件、批量下载和高频 Variant 处理需要更严格配额。
- 发现页只展示审核通过内容，避免公开滥用造成流量爆发。
- 检测异常 Referer、单图片高频访问和短期流量突增。
- 发生异常时可以暂停新上传、关闭发现页或撤销泄露 Token，不影响用户删除和导出。

## 9. 套餐成本设计原则

套餐不只按存储收费，还要同时约束：

```text
存储容量 + 外链流量 + API 次数 + 处理次数 + 并发 + 单文件大小
```

Free 套餐优先保证低频真实使用；Creator 套餐应覆盖稳定外链和创作者管理；Pro 套餐才提供高 API 速率、自定义域名、防盗链和 Webhook。

当成本异常时，优先临时限制流量、并发和新上传，不直接删除用户已有数据。

## 10. 成本监控指标

- 每日新增原图字节数
- 每日新增派生图字节数
- 回收站总量和清理积压
- 孤儿对象数量
- 每用户平均存储和流量
- Free 用户存储/流量 P95
- 单 Token、IP 和 Referer 流量排行
- 处理任务平均成本和失败重试量
- 对象存储错误率和回源流量

这些指标应进入管理端运营仪表盘，并设置异常增长告警。

## 11. 本地开发磁盘与 SSD 约束

开发机上的 Go 构建缓存、前端依赖和临时预览产物不属于 FastImg 业务数据，不能因为一次测试或一次重启不断复制保留。

### 11.1 单一缓存原则

- 一个 checkout 只使用一个 `GOCACHE`，禁止使用 `.gocache-<功能>-<版本>` 这种按任务分裂的目录。
- Windows 使用 `scripts/fastimg-go.ps1`，WSL/Linux 使用 `scripts/fastimg-go.sh`；默认缓存位于用户缓存目录，避免污染 `D:\laragon\www\fastimg`。
- `go test -count=1` 只表示不复用测试结果，不应通过新建 GOCACHE 来实现“隔离”；编译缓存仍应共享。
- 需要真正隔离时使用临时 checkout 或容器，并在任务结束时销毁临时缓存，不得把隔离缓存留在仓库中。

### 11.2 稳定运行产物

- 后端开发服务覆盖写入 `backend/.runtime/fastimg-dev.exe`，日志使用 `fastimg-dev.log`，PID 使用 `fastimg-dev.pid`。
- 不以时间戳、端口或功能名不断生成新的开发二进制。需要保留崩溃现场时只复制一次，并注明保留期限。
- `admin/node_modules` 可以重建；`.tmp-dist`、Vite 缓存、Go 缓存可以清理；`backend/storage/fastimg`、回收站、数据库导出和业务日志必须单独确认。

### 11.3 开发预算与清理

本地默认预算为：Go/前端缓存不超过 8 GB，运行产物不超过 1 GB，日志不超过 500 MB。每个阶段验收前执行：

```powershell
pwsh -File scripts/fastimg-disk-audit.ps1
```

清理命令默认只预览，必须显式确认后才执行：

```powershell
pwsh -File scripts/fastimg-clean-dev-artifacts.ps1
pwsh -File scripts/fastimg-clean-dev-artifacts.ps1 -Apply
```

清理工具不会删除媒体目录；旧运行二进制和 `storage/bin` 需要额外开关并在确认进程未使用后处理：

```powershell
pwsh -File scripts/fastimg-clean-dev-artifacts.ps1 -Apply -IncludeOldRuntime -IncludeStorageBin
```

### 11.4 SSD 写入说明

当前 48 GB 主要是重复缓存和开发二进制，不是每次都在写入 48 GB。重复缓存会造成不必要的编译和 SSD 写放大，但偶发几十 GB 的累计开发写入通常远低于普通 SSD 的 TBW 额定寿命；真正需要避免的是长期、无上限地为每次测试建立新缓存。单一缓存、稳定产物和预算检查可以同时降低磁盘占用、编译时间和写入量。
