# FastImg 生产开发就绪评估

## 1. 结论

当前文档已经足够进入生产级开发，但还不代表系统可以直接上线生产。

### 可以立即开始

- Free 用户注册、套餐、配额、上传、媒体库、删除/恢复和基础稳定链接。
- Personal API Token、API 上传、链接获取、自己媒体删除和 API 限流。
- 审核、举报、发现页开关、违规图片和账户处置。
- Local Storage + fake/offline 图片处理、fake/manual 审核和 fake/manual 支付。
- 管理端会员、媒体、套餐、广告位、任务和基础统计。

### 暂不能直接宣称生产可用

- 真实法币支付 Provider。
- 真实加密货币链上支付、风控和退款。
- 自定义域名、证书自动续期、CDN 和大规模外链流量。
- 税务发票、跨地区税费、自动退款和完整财务对账。
- 多副本部署、灾备恢复、对象存储跨区域复制和高并发压测。

这些能力已经有接口和数据契约，但必须完成真实环境验证后才能从 `designed` 标记为 `verified`。

## 3. 开发前必须锁定的决策

1. 首个可上线版本是否只包含 Free + fake/manual 支付，真实支付放在独立里程碑。
2. 首期对象存储使用 Local 还是 S3-compatible；生产不允许只验证 Local 就宣称对象存储可用。
3. 图片处理器首期使用哪个受限 Provider，以及最大像素、内存、超时和并发值。
4. 站点部署地区、隐私政策、数据保留期限和加密货币支付适用地区。
5. 真实法币和加密支付是否使用托管 Provider；MVP 不自建钱包和私钥系统。
6. 生产域名、CDN、证书、备份、告警和恢复负责人。

这些决策不应写成散落在代码中的常量，应进入站点配置、套餐权益或 Provider 配置，并可审计变更。

## 4. 推荐开发顺序

### 阶段 A：Free 生产级基础

完成账户、Free 套餐、配额、上传、媒体库、Local/S3 Provider、Variant、删除恢复、审计、Redis 队列和基础监控。

### 阶段 B：开发者与治理

完成 Personal API Token、API 幂等与限流、链接响应、审核、举报、账户处置、发现页和数据导出/注销。

### 阶段 C：商业化模拟

完成套餐升级、订单、支付意图、支付流水、fake/manual Provider、订阅履约、广告免除和退款模拟。

### 阶段 D：真实支付与加密支付

每个 Provider 单独通过签名、回调、重复事件、金额校验、退款、对账和故障演练后才能启用。加密支付还必须通过确认数、链重组、风险地址、少付、多付和错误网络测试。

### 阶段 E：生产发布

完成真实对象存储、备份恢复、CDN/防盗链、压测、告警、发布回滚、隐私/合规审查和灾备演练。

## 5. 生产开发门禁

### Gate 0：基线

- 仓库、模块边界、数据库和 Redis 连接已确认。
- 后端测试、前端类型检查和构建基线已记录。
- PostgreSQL 迁移、队列、文件系统和 OpenAPI 入口已确认。

### Gate 1：Free 闭环

- 新用户不付费即可上传、查看、复制链接、删除和恢复。
- 并发上传不能突破容量、文件大小、每日上传和处理限制。
- 用户无法访问其他用户媒体、Token、用量或分享配置。
- 对象、数据库、队列和图片处理失败均可查询、重试或补偿。

### Gate 2：安全与治理

- 恶意图片、伪造 MIME、超大像素、SVG 风险和 EXIF 清理有测试。
- 审核、举报、封禁、申诉、发现页停用和永久删除可审计。
- API Token、分享 Token、密码、支付敏感字段和私钥材料不出现在日志。

### Gate 3：支付

- fake/manual 支付可完成订单、支付意图、回调、履约、退款和补偿。
- 真实 Provider 未通过签名、回调、金额、重复事件和退款测试前不能启用。
- Crypto Provider 未通过确认数、链重组、风控和差额测试前不能启用。

### Gate 4：运行与恢复

- PostgreSQL、对象存储、配置和密钥有备份/恢复流程。
- Redis 丢失后系统不会丢失唯一业务事实。
- 队列积压、对象错误、支付回调失败、异常流量和存储增长有告警。
- 至少完成一次代码回滚、数据库兼容迁移和对象恢复演练。

## 6. 发布报告必须区分的状态

所有外部能力只能使用以下状态：

```text
designed  - 已有文档和接口设计
implemented - 已完成代码和单元/契约测试
integrated - 已连接真实 Provider 并通过集成测试
verified - 已在目标生产配置完成失败和恢复演练
enabled - 已在生产开启
disabled - 已实现但因风险或配置暂未开启
```

`designed`、`implemented` 或 `fake/offline` 不能写成“生产支付已完成”。
