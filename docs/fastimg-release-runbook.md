# FastImg 开发、发布与恢复手册

## 1. 本地开发前检查

生产部署脚本和外部数据库/Redis约束见 [fastimg-deployment.md](./fastimg-deployment.md)。脚本不会启动 PostgreSQL 或 Redis 容器，也不会把真实支付、备份恢复或对象存储验收伪装成已完成。

PostgreSQL 和 Redis 由 Laragon 管理。开发、迁移或联调前检查：

```powershell
Test-NetConnection 127.0.0.1 -Port 5432
Test-NetConnection 127.0.0.1 -Port 6379
```

检查 `backend/.env` 的数据库和 Redis 配置，不擅自更换安装路径或连接方式。Redis 不可用时不得改成内存实现来伪造成功。

## 2. 本地启动顺序

```powershell
cd backend
go run .
```

另一个终端：

```powershell
cd admin
pnpm install
pnpm dev
```

后台服务必须以可持续进程方式启动并保存日志。向用户提供地址前，必须从启动日志确认真实端口；不要假设端口一定可用。

## 3. 数据库迁移流程

1. 生成迁移文件。
2. 人工检查表名、外键、索引、软删除、唯一约束和回滚边界。
3. 备份目标数据库或确认本地数据库可重建。
4. 在 PostgreSQL 上执行迁移。
5. 执行资源 Seed/权限注册。
6. 运行模型、Repository、权限和 CRUD 测试。
7. 记录迁移版本和验证结果。

禁止：

- 在应用启动时偷偷修改数据库结构。
- 未审阅就执行生成器产生的迁移。
- 用删除数据库或重置所有数据解决迁移失败。
- 把 PostgreSQL 未验证的行为当作 MySQL 兼容能力。

## 4. 队列和任务检查

上线前至少验证：

- 上传完成任务能进入 Redis queue。
- Worker 能处理缩略图、审核、清理和统计任务。
- 失败任务写入失败记录，具有重试次数和错误原因。
- 重试不会重复扣减额度、重复生成有效 Variant 或重复发放套餐。
- 队列不可用时 API 返回可理解的处理中/稍后重试状态，而不是标记完成。
- 管理员可在 `/admin/tasks` 查看失败任务摘要；该页面只需要 `admin.tasks.view`，重新投递需要额外的 `admin.tasks.retry`。
- 失败任务中心只展示 UUID、连接、队列、任务签名和失败时间，不把原始 payload、异常堆栈或密钥直接返回浏览器；重新投递必须在审计日志中留下 `queue.task.retry`。

## 5. 发布前检查

### 代码和契约

- [ ] `go test ./...` 通过。
- [ ] `pnpm exec vue-tsc --noEmit` 通过。
- [ ] `pnpm run build` 通过。
- [ ] `/api/openapi.json` 包含本阶段新增接口。
- [ ] TypeScript Client 已通过生成脚本更新。
- [ ] 错误码、权限、数据范围和字段策略已审阅。

### 数据和基础设施

- [ ] PostgreSQL 备份可用，迁移版本已记录。
- [ ] Redis 连接、队列和限流可用。
- [ ] 文件系统/对象存储读写验证通过。
- [ ] 上传、处理、清理和审核失败任务有监控入口。
- [ ] 存储、带宽、队列积压和审核积压有告警阈值。

### 安全和业务

- [ ] 用户 A 无法访问用户 B 的媒体、分享配置、用量和 API Key。
- [ ] Personal API Token、分享 Token、密码和支付敏感数据不出现在日志。
- [ ] 未审核媒体不进入发现页。
- [ ] 上传大小、像素、MIME、速率和配额限制已验证。
- [ ] 管理员额度调整、封禁、审核和永久删除可审计。
- [ ] Free 用户不付费即可完成上传、管理和基础分享。

## 6. 发布顺序

```text
备份 -> 进入维护/限制写入 -> 执行迁移 -> 注册权限/资源
  -> 启动 Worker -> 部署后端 -> 部署前端
  -> 冒烟测试 -> 恢复正常流量 -> 观察指标
```

迁移和代码必须保持向后兼容：先发布能读旧/新字段的代码，再执行新增结构变更；删除字段或旧状态必须单独发布，不能和新增功能混在一次不可逆变更中。

## 7. 冒烟测试

1. 新建 Free 用户。
2. 上传一张允许格式图片。
3. 检查媒体状态从 processing 到 ready。
4. 获取缩略图和 Markdown 链接。
5. 创建分享链接并验证过期/密码策略。
6. 创建 API Key，通过 API 上传一张图片。
7. 删除并恢复媒体。
8. 提交一条举报并在后台处理。
9. 检查用量流水和审计记录。
10. 重试一个失败任务并确认不会重复计费。

## 8. 回滚策略

### 代码回滚

- 回滚到上一阶段本地提交或已验证构建产物。
- 保留新增数据库字段和表，只回滚应用读取/写入逻辑。
- 不使用破坏性数据库重置。

### 数据回滚

- 账务、用量、审计和订单记录优先使用冲销/补偿流水，不直接删除。
- 对象误删只能从对象存储备份恢复；没有备份不能承诺恢复原图。
- 迁移回滚必须先确认没有新代码依赖该结构。

### 功能降级

- 暂停新上传但允许下载、删除和导出。
- 暂停公共发现页但不影响私有媒体。
- 审核服务不可用时进入人工审核。
- 支付服务不可用时停止新订单，不修改已有订阅。

## 9. 运行指标

至少观察：

- 上传成功率和完成确认失败率
- 处理任务成功率、P95 耗时和失败积压
- 队列长度和最老任务等待时间
- 对象存储读写错误率
- API 429 比例和异常流量
- 审核待处理量和举报处理时长
- 每日新增存储、外链流量和孤儿对象数量
- 订单回调成功率和重复事件数量

## 10. 生产门禁工具

以下工具默认不会安装依赖、修改锁文件、删除数据库或写入真实支付渠道：

```powershell
# 生成并验证 PostgreSQL 自定义格式备份；默认输出到系统临时目录
pwsh -File .\scripts\fastimg-db-backup.ps1 -VerifyDump

# 依赖扫描缺工具或未批准联网时会 fail-closed
pwsh -File .\scripts\fastimg-dependency-audit.ps1

# 只访问公开状态接口，不执行上传、订单或支付写操作
pwsh -File .\scripts\fastimg-load-smoke.ps1 -BaseUrl http://127.0.0.1:53085 -Requests 100 -Concurrency 10
```

真实支付回调、TLS/反向代理、隔离库恢复、对象存储/CDN 和正式压测的验收步骤见 [fastimg-production-gates.md](./fastimg-production-gates.md)。
