# FastImg 合规、隐私与内容规则

本文档是产品、审核和工程实现的基线，不替代针对具体运营地区的法律意见。正式上线前应由运营方根据实际主体、地区和存储位置审核服务条款与隐私政策。

## 1. 用户责任

用户必须：

- 只上传自己拥有或获得合法授权的内容。
- 不上传违法、侵权、欺诈、恶意软件、隐私泄露或危害他人的内容。
- 不使用图床进行钓鱼、垃圾信息、恶意跳转或规避平台审核。
- 保护自己的登录凭证和 Personal API Token。
- 在使用 API 时遵守速率、存储、流量和套餐限制。

用户对自己上传、公开、分享和通过 API 分发的内容承担责任。

## 2. 平台处理权

平台可以根据服务条款和内容治理策略：

- 暂停公开展示或发现页投稿。
- 隐藏、删除或限制访问违规媒体。
- 限制上传、API、分享或账户功能。
- 暂停或封禁账户。
- 保留必要的审计、订单、举报和安全证据。
- 在法律要求、账号安全或重大滥用情况下采取紧急措施。

处理动作必须记录原因、证据引用、操作者、时间、影响范围和恢复/申诉规则。

## 3. 版权投诉

版权投诉至少需要：

- 投诉人的身份和联系方式。
- 被投诉媒体 URL 或媒体标识。
- 权利证明或授权关系说明。
- 对侵权事实的具体描述。
- 投诉人真实、完整的声明。
- 提交时间和电子签名/确认。

处理流程：

```text
收到投诉 -> 校验材料 -> 暂时隐藏或进入复核 -> 通知上传者
  -> 接受反通知/申诉 -> 复核 -> 维持、恢复或删除
```

版权投诉不自动等同于永久封禁账户；重复、恶意或明确侵权行为可以根据治理策略升级处罚。

## 4. 隐私和 EXIF

默认处理：

- 清理 GPS、拍摄设备、序列号和其他可能识别个人的信息。
- 原图是否保留 EXIF 由站点配置和套餐规则决定。
- 公开发现页不得展示原始 EXIF 或私有对象路径。
- 图片访问统计使用最小化数据，IP 地址按隐私策略截断、哈希或限期保留。
- 审核员只在必要权限下查看敏感原图。

用户界面必须在上传设置或隐私说明中告知 EXIF 清理行为；不能让用户误以为处理后的文件与原始字节完全相同。

## 5. 数据保留

| 数据 | 默认保留策略 |
| --- | --- |
| 活跃媒体 | 按用户和套餐规则保留 |
| 回收站媒体 | 由站点配置天数后永久清理 |
| 失败上传会话 | 超时后清理对象和会话 |
| 审计日志 | 按安全和合规策略保留 |
| 举报和处罚 | 保留处理历史和证据引用 |
| 订单和支付事件 | 按财务/法律要求保留 |
| 访问事件 | 聚合后按隐私策略清理原始事件 |
| API Token | 撤销后保留非敏感元数据，不保留原文 |

清理任务必须幂等、可重试并记录释放的对象和额度。不能通过直接删除数据库记录跳过对象清理和审计。

## 6. 用户数据控制

用户应能：

- 查看和删除自己的媒体。
- 恢复回收站中的媒体（在对象仍存在且额度允许时）。
- 撤销 Personal API Token。
- 导出自己的媒体链接和基本元数据。
- 查看有效处罚、申诉和处理结果。
- 注销账户并了解媒体、订单、审计和举报记录的保留边界。

注销账户前应明确展示：媒体数量、占用空间、未完成订单、Token 数量和不可恢复项。

## 7. 安全事件

发现 Token 泄露、对象公开、跨用户访问、批量删除或异常流量时：

1. 标记事件并生成 request/incident ID。
2. 暂停受影响 Token、链接、账户或存储 Provider。
3. 保留必要日志和证据，避免扩大暴露。
4. 修复权限、缓存、对象策略或任务状态。
5. 验证没有继续越权访问。
6. 根据适用规则通知受影响用户和运营负责人。
7. 形成事件报告和回归测试。

## 8. 公开文案要求

上线前必须准备并链接：

- 服务条款
- 可接受使用政策
- 隐私政策
- 版权投诉入口
- 内容举报入口
- 账户处罚和申诉说明
- 数据删除和导出说明

这些文案不能只存在后台配置中，用户在上传、分享、发现页、Token 创建和账户注销流程中都应能访问相关说明。
