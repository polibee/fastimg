# 会员端与管理端路由及职责分离设计

日期：2026-09-23

状态：已确认（设计稿；未实施）

## 1. 背景与目标

FastImg 的会员页面和管理页面目前共用一个 Vue 应用，但入口结构容易让人误认为它们是同一类页面：会员功能位于 `/app/**`，而根路由和若干资源页面由管理端 `AdminShell` 承载。用户希望面向会员的 URL 简洁、无需 `/app/` 前缀，登录后首先进入以上传为中心的轻量页面；管理后台则明确服务于管理员及运营人员，管理全站对象和运营配置。此调整须同时澄清页面职责、导航和授权边界，不得把路由变化误当成服务端跨用户授权。

本设计的目标：

1. 根路径成为登录会员的上传首页，会员常用路径采用 `/media`、`/plans` 等扁平 URL。
2. 管理端统一收敛到 `/admin/**`，只由有后台管理权限的用户进入。
3. 会员端只管理认证身份拥有的媒体和个人资料；管理端跨用户操作必须有独立 API、RBAC、数据范围和审计支撑。
4. 复用现有 Vue Router、Shell、认证、API Client、i18n、资源生成器和组件，不复制框架能力或领域逻辑。
5. 明确 URL 冲突、旧链接迁移、登录落点、导航可见性和验收条件。

## 2. 当前已核实状态

- `admin/src/router/index.ts` 当前把 `/app/**` 挂在 `MemberShell`，而根 `/`、`/media`、`/plans` 和生成资源路由由 `AdminShell` 承载。
- 会员 `/app/media` 已有本人媒体上传、预览、搜索、软删除和回收站恢复；`/app/plans` 已有本人套餐/用量只读页面。会员导航目前只有媒体和套餐入口，未提供上传首页。
- 管理端 `/media` 与会员媒体页调用同一组 `/api/v1/media` own-scope 接口。`backend/app/modules/media/controllers/media_controller.go` 从认证上下文取得当前用户 ID，再传给媒体库服务；当前管理端媒体页因此不是全站媒体管理。
- 文件夹和相册资源的 manifest 使用 own 数据范围及 `user_id` 归属。它们当前不构成管理员跨用户管理能力。
- 管理端 `/plans` 是套餐资源管理；会员 `/app/plans` 是本人套餐/用量读取。二者页面用途不同，路径冲突只是 URL 空间上的冲突。
- 当前若把 `/` 改为会员首页，原管理首页必须迁移到 `/admin`。当前 `/media`、`/plans` 将明确归会员端所有；套餐管理迁移到 `/admin/plans`。`/admin/media` 暂不注册，直至全站媒体 API 和权限审计具备后再开放。

以上为代码现状，不代表本设计已实现。

## 3. 体验和职责边界

| 项目 | 会员端 | 管理端 |
| --- | --- | --- |
| 入口/布局 | `/`，`MemberShell` | `/admin/**`，`AdminShell` |
| 主要对象 | 当前登录人的媒体、用量、订阅及账号 | 经 RBAC 明确授权的会员、套餐、广告、站点设置、审核、举报、订单和全站统计 |
| 默认数据范围 | 服务端强制 own-scope；所有者取自认证身份 | 由后台权限和数据范围决定；敏感操作执行审计 |
| 导航 | 首页/上传、我的图片、套餐与用量；仅在有权限时显示“管理后台”入口 | 仅显示用户有权访问的管理功能 |
| 共用能力 | 同一 Vue 工程、登录态、API Client、i18n、基础组件、后端领域服务 | 同左；页面职责和访问策略保持独立 |

套餐权益只影响会员额度和功能，不能赋予管理权限。管理员也是普通会员时仍可访问会员端；管理角色不改变会员页面的数据范围。不得根据“管理员身份”把 `/media` 或 `/plans` 自动重定向到管理页面。

### 3.1 会员首页

`/` 使用简洁的上传优先布局，不做运营仪表盘式 KPI 卡片堆叠：

- 页面焦点是拖放/选择图片区域，并提供键盘可操作的文件选择入口。
- 展示上传队列的进度、处理中、成功、失败和重试状态；只有媒体后端确认 ready 才显示完成和链接操作。
- 上传区下方展示少量最近图片；“查看全部”进入 `/media`。空状态直接引导首次上传。
- 展示精简的当前套餐/可用空间提示，并链接到 `/plans`；不重复实现配额计算。
- 调用现有上传和会员媒体 API；认证身份及 owner-scope 由服务端决定，不提交客户端 `user_id`。
- 页面文案通过现有 vue-i18n namespace 同步提供 `zh-CN`、`en-US`；颜色、间距和控件复用项目语义 token 与 shadcn-vue 组件。

### 3.2 会员导航

`MemberShell` 提供清晰且响应式的主导航：`首页/上传`（`/`）、`我的图片`（`/media`）、`套餐与用量`（`/plans`）。具备至少一个有效后台管理权限时可显示进入 `/admin` 的链接；无权限时隐藏该入口。不得在目标会员页面和相应 API 尚未落地前展示文件夹、相册、Token、订单或分享链接入口。

### 3.3 管理端

管理端首页迁移到 `/admin`，保留 `AdminShell` 及现有 RBAC、审计和资源页面能力。后台资源 URL 在 `/admin/**` 下统一组织，包括 RBAC、审计日志、套餐、广告及其他已生成资源。所有侧栏、首页快捷入口、面包屑、资源生成菜单和程序化导航都必须生成此命名空间下的地址。

路由归入管理端并不会改变其 API 数据范围。当前 own-scope 的文件夹/相册资源不注册为 `/admin/**` 管理资源；在它们拥有会员端页面之前，后端现存资源可以保留，但前端不提供误导性的管理入口。管理端媒体审核/按用户查看能力需要后端显式管理用例、细粒度权限、数据范围和审计。此路由切片不注册 `/admin/media`：现有仅能查看当前用户媒体的 Admin `/media` 页面迁移后由会员 `/media` 承接；全站媒体管理待其服务端管理 API 和授权审计能力完成后再单独接入。不得复用 own-scope 会员页冒充后台功能。

## 4. 路由契约

| URL | Shell / 访问范围 | 结果 |
| --- | --- | --- |
| `/` | MemberShell；需登录 | 上传优先会员首页 |
| `/media` | MemberShell；需登录 | 本人媒体库 |
| `/plans` | MemberShell；需登录 | 本人套餐和用量 |
| `/admin` | AdminShell；需有效后台管理权限 | 管理首页 |
| `/admin/rbac`、`/admin/audit-logs` | AdminShell；具体 RBAC 权限 | 现有管理页面迁移后的 URL |
| `/admin/plans` | AdminShell；套餐管理权限 | 全站套餐资源管理 |
| `/admin/<resource>` | AdminShell；资源权限 | 已启用且确属管理范围的资源；资源 URL 统一加管理前缀。own-scope 文件夹/相册不在此注册 |
| `/discover` | 公共路由（若现有功能已注册） | 仅访问公开、审核通过内容；不因会员壳迁移而改变 |
| `/login` | 认证页 | 登录后优先回到显式有效的 `redirect`，否则 `/` |
| `/app`、`/app/media`、`/app/plans` | 兼容重定向 | 分别重定向到 `/`、`/media`、`/plans` |

`/admin` 父路由和所有子路由都执行认证及后台授权。父路由守卫负责拒绝无管理权限的用户；已有子页面 RBAC 检查继续保留，不以父级“有后台入口”取代具体操作权限。未登录访问管理深链先去登录，登录成功后仅在目标仍经授权时返回原地址。

登录页没有显式 redirect 时统一进入 `/`，即使用户兼具管理权限；管理员可从会员导航进入后台。这样避免同一账号的根路径含义随角色改变。

### 4.1 历史链接与冲突处理

- `/app/**` 中已经存在的会员路径提供兼容重定向；未实现的旧会员子路径不应静默映射到不相关页面。
- 原管理首页 `/` 无法与会员首页共存，原管理地址统一改用 `/admin`。
- 原管理 `/media`、`/plans` 与新会员 `/media`、`/plans` 发生真实冲突。会员 `/media` 承接现有个人媒体页面，管理 `/plans` 迁移为 `/admin/plans`；本切片移除伪装全站管理的旧 Admin `/media`，不注册 `/admin/media`，直至有独立全站 API/权限/审计。会员占用的冲突 URL 不做基于角色的歧义重定向。
- 其他原管理资源路径统一迁移到 `/admin/<resource>`。若项目已有外链兼容需求，只对无会员路由冲突的旧地址增加明确的静态重定向，并设置测试；不得靠 catch-all 或角色猜测路由。
- 不能仅更改页面链接而遗漏 Vue Router 名称、资源生成器的 path、仪表盘链接和硬编码 `router.push`。

## 5. 技术实现约束

1. 保持单一 Vue Router；通过嵌套路由和独立 Shell 清晰区分体验，不建立第二套前端工程或认证状态。
2. 管理路由前缀集中定义/组合。`admin/src/core/resource/generated.ts` 等生成产物遵循生成流程更新；不得手改生成产物绕过生成器。若资源 path 当前为绝对路径，路由装配层统一将其挂到 `/admin`，避免重复前缀。
3. `dashboardResourceRoute`、管理员侧栏、管理首页快捷入口、面包屑和命令式导航共用一致的管理路由解析规则。
4. 路由守卫复用现有认证与 `auth.canAny`/权限状态机制；后端仍是最终授权边界，前端隐藏导航不作为安全措施。
5. 会员页复用当前 MemberMediaPage 的 API 模式与上传状态机制。不得为了换 URL 新增重复上传服务、媒体服务或配额计算。
6. 此次仅做前端路由/壳/导航/文档和相应测试；不改数据库、迁移、Redis、后端数据范围或生产服务。
7. 不因管理路由收拢而扩展 API 权限。跨用户媒体管理作为依赖明确列入后续开发；应另行设计和测试后端 API/RBAC/审计闭环。

## 6. 错误和访问体验

- 未登录：保存目标路由为 redirect，登录后验证权限，再回目标。
- 已登录但无后台权限：访问 `/admin/**` 显示无权访问页/安全返回会员首页，不泄露管理数据。
- 页面级权限不足：保留现有 403 页面与资源授权行为，不因管理员外壳而绕过。
- 上传 API 失败、限流或配额不足：在会员首页内联显示本地化错误和可执行的重试/管理媒体/查看套餐入口；不误报成功。
- 首页及导航在窄屏、键盘操作、加载中和空列表状态下可用；状态不能只依赖颜色，遵守 reduced-motion 设置。

## 7. 文档与测试验收

### 7.1 代码验收

- 路由表断言 `/`、`/media`、`/plans` 使用 MemberShell；管理页仅在 `/admin/**` 并使用 AdminShell。
- 验证 `/app` 兼容重定向，且会员深链的参数/查询按约定保留。
- 验证未登录、普通会员、管理员及同时具备两类身份的路由守卫和默认落点；不得角色推断 `/media` 的意义。
- 验证无后台权限用户看不到后台入口且不能进入 `/admin`，有权限用户能进入并仍受子页 RBAC 约束。
- 检查所有管理侧栏、资源生成路由、仪表盘快捷入口、面包屑及命令式导航不再误指旧根路径。
- 检查会员请求不提交 `user_id`，后端 own-scope 未发生变化；不得声称 `/admin/media` 已有跨用户读取能力，除非另有已测试的管理 API。
- 首页验收覆盖图片选择/拖放、队列状态、处理完成判断、错误/重试、最近媒体、空状态、响应式布局和键盘可达性。
- 所有新增可见文案同时维护 `zh-CN`/`en-US`，通过 `admin/tests/fastimg-i18n.test.mjs`。
- 运行前端相关测试、`pnpm exec vue-tsc --noEmit` 与 `pnpm run build`。浏览器验收分别使用普通会员和管理员账号；若环境不可用，报告为未验证，不伪称通过。

## 8. 分阶段实施顺序

设计批准并进入计划阶段后，按以下依赖顺序实施，不以单个组件完成为由停下来请求确认：

1. **路由与守卫骨架**：将 AdminShell 收到 `/admin/**`；会员 Shell 成为 `/` 默认入口；增加权限守卫和 `/app` 兼容跳转；为冲突旧管理路径制定静态迁移。
2. **会员导航与首页**：完成上传优先的 `/` 页面，导航改用扁平路径，连接已有媒体/套餐 API，处理上传完整状态和失败状态。
3. **管理导航与生成资源**：更新管理菜单、资源路由前缀解析、仪表盘链接、面包屑和所有硬编码入口；确保各资源权限未被放宽。
4. **双语、回归与文档**：更新中英文、路由/权限/i18n 测试，运行前端测试、类型检查和构建，完成两个 Shell 的浏览器回归；同步设计/阶段/进度文档。

管理端真正按用户管理全站媒体不属于以上前端路由切片的完成条件；该能力必须另有服务端授权设计与验收，不得在本次通过客户端过滤或复用 own-scope API 拼接。

## 9. 排除范围

- 本次不新增真实的跨用户媒体 API、审核处罚 API、用户管理 API 或支付流程。
- 不扩大任何数据库或 RBAC 权限，不运行迁移，不修改 Laragon PostgreSQL/Redis 配置。
- 不重做全站视觉系统、不复制 Admin Core/RBAC/i18n/资源生成器、不引入第二个 SPA。
- 不把尚未实现的会员模块加入导航，也不宣称项目或支付已达到生产就绪。

## 10. 决策摘要

- 用户端公开 URL 从 `/app/**` 扁平化，根路径 `/` 是登录会员的上传首页。
- 管理端所有页面统一置于 `/admin/**`；旧 `/media`、`/plans` 冲突地址归会员端，不做角色相关的隐式切换。
- `/app`、`/app/media`、`/app/plans` 保留静态兼容重定向。
- 会员始终 own-scope；管理员全站管理必须由独立后端管理 API、RBAC、数据范围和审计支撑。
- 本文件只记录设计；代码与业务 API 现状均未因写本文而改变。
