# FastImg 后台设置布局设计

## 目标

让管理员按业务理解设置，而不是按数据库字段理解设置；统一输入框、开关和选择框的尺寸、位置和提示，避免配置项拥挤或错位。

## 分组顺序

后台 `/admin/settings` 固定使用以下顺序：

1. 站点基础
2. 注册与登录
3. 邮件服务
4. 上传与媒体
5. SEO 与发现页
6. 支付与订单
7. 统计
8. 自定义代码
9. 其他设置

备份与恢复不放入普通设置表单，独立放在 `/admin/backups`，并使用更高风险的操作确认。

## 表单布局

- 所有业务设置使用统一的 shadcn-vue `Field`、`FieldLabel`、`FieldDescription` 和 `FieldGroup`。
- 文本输入、数字输入和选择框统一 `w-full`，在双列布局中保持相同高度。
- `Select` 统一使用 shadcn-vue `SelectTrigger`、`SelectValue`、`SelectContent` 和 `SelectItem`，移除原生 `<select>`。
- 布尔值使用横向开关/复选控件，标签和说明与控件同一行对齐。
- 密钥字段保持密码输入和“已配置”占位符，不在前端回填明文。
- 邮件服务只显示当前 provider 的专属字段，SMTP、阿里云和 Resend 不再全部堆叠。
- 支付渠道保留独立区块，官方 API 地址和回调地址放在凭证字段之后，并保持统一网格。
- 长文本使用跨两列的 `Textarea`，代码字段明确显示用途和风险提示。

## 交互规则

- 切换邮件服务时只改变显示字段，不自动清空其他服务已保存的配置。
- 保存只提交修改过的字段；密钥留空表示保持原值。
- 选择框的当前值必须通过模型绑定显示，不能依赖原生 `value` 属性和手工事件混用。
- 保存失败时明确显示具体分组和字段名称。
- 中文和英文 Key 必须同步维护。

## 验收

- 设置页面按九个业务分组显示。
- 所有选择框尺寸和左右边界一致。
- 邮件 provider、SMTP 加密方式和支付环境使用统一选择组件。
- 桌面双列和窄屏单列均不发生控件溢出。
- 切换 provider 后保存不会清空其他 provider 的密钥。
- 中英文设置页面 Key 集合一致。
