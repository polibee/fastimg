# FastImg 前端应用边界

当前项目仍然使用一个 Vite/Vue 应用，但已经把路由入口拆成两个应用边界：

- `member/`：C 端和公开页面，只能挂载 `MemberShell` 与会员页面。
- `admin/`：管理员后台，只能挂载 `AdminShell`、后台资源页面和管理员业务页面。
- `core/`、`components/`、`lib/`、`stores/`：共享基础设施，不属于任一应用页面。

这一步不改变 URL、不复制 API 客户端，也不改变权限规则。后续迁移到同层 `web/` 时，应从 `member/` 边界开始抽取，并把真正需要共享的 API 契约、i18n、UI 和认证基础设施迁移到 workspace package。

## SSR/SSG 约束

应用边界抽取本身不会自动启用 SSR。它的作用是让 `web` 可以拥有独立入口、服务端数据加载和 SEO 生命周期，而管理后台继续保持 SPA。

- 当前 `build:ssg` 是静态预渲染路线，已覆盖首页、套餐和发现页；公开相册通过 `SSG_PUBLIC_ALBUM_IDS` 指定后生成 `/a/:id/` 入口。未指定的相册不会被预渲染，私有相册也不会进入公开 HTML。
- SSG 生成的每个公开入口保留 `#app` 挂载点，并在挂载点内放置可抓取的标题、描述和行动链接；浏览器加载 Vue 后继续接管页面，不能只生成脱离应用的静态 HTML。
- 真正 SSR 需要额外的服务端渲染运行时、服务端入口、请求级数据加载、head 管理和部署适配。
- 私有媒体、Token、订单和 `/admin/**` 不得进入公开预渲染或服务端缓存。
